# cloudtidy

Local-first iCloud Drive document organizer: Bun + strict TypeScript orchestration and small Swift helpers that call **Apple Foundation Models on-device only** (no cloud, no model server, no runtime network access, no third-party runtime dependencies).

**Read-only by default.** Nothing is moved unless you pass `--apply` (or set `daemon.apply: true` for the LaunchAgent). Nothing is ever deleted or overwritten. Everything uncertain, duplicated or failed goes to `_Inbox/Needs_Review`.

> Status: all code is implemented and covered by mocked/sandbox tests on Linux (`bun test`). Apple model inference, Vision OCR, `launchd` and iCloud behaviour have **not** been run yet — they need your Apple-silicon Mac. See [Verify on your Mac](#verify-on-your-mac) and `PLAN.md`.

## Requirements

- Apple-silicon Mac, macOS 26+, Apple Intelligence enabled and its model downloaded.
- Xcode 26+ (macOS 26 SDK; `xcode-select -s` to it).
- Bun 1.3.2+. Optional: `brew install poppler` for PDF text layers (Vision OCR is the fallback).

## Setup

```sh
bun install --frozen-lockfile
bun run build:helpers          # builds + ad-hoc signs bin/classify and bin/ocr (arm64, macOS 26)
bun src/cli.ts doctor          # helpers, model availability, inbox, exclusive rename, LaunchAgent
```

```sh
bun src/cli.ts init            # preview: which taxonomy folders are missing
bun src/cli.ts init --yes      # create them (only after iCloud Drive has fully synced!)
```

**Taxonomy (11 folders).** Besides `_Inbox` and `_Inbox/Needs_Review`, `init` creates the buckets and every configured route folder: `01_Uni`, `02_Admin & Finanzen` with the sub-folders `Rechnungen`, `Verträge`, `Bank`, `Steuern` and `Belege`, `03_Projekte & Dev` and `04_Persönlich`. Documents that fit none of the five sub-folders (authorities, SVS/ÖGK, official notices) stay in the `02_Admin & Finanzen` root (route `admin`, decided by the model only).

**Upgrading from a version without the Bank/Steuern/Belege sub-folders.** Run `bun src/cli.ts init` (preview) and then `init --yes` once, after iCloud Drive has synced: it creates exactly the three new folders and nothing else. Until then `doctor` shows "taxonomy folders" as ✗ and files for the new routes go to `_Inbox/Needs_Review` with `folder_missing:02_Admin & Finanzen/Bank` (or `Steuern`/`Belege`); nothing is lost. **Config files are replaced, never merged:** `config/default.config.json` in the repo is picked up on `git pull`, but a copy that you passed to `install --config <file>` (or `--config` on any command) keeps its old routes. An old copy still has a single `admin` route with the bank/tax/receipt patterns that sends those documents to the `02_Admin & Finanzen` root. To upgrade it, replace its `admin` route by the four routes `bank`, `tax`, `receipts` and `admin` from `config/default.config.json` (the `admin` route now has `"patterns": []`), then run `init --yes --config <file>`. No `uninstall`/`install` is needed because the config is re-read on every run. Already filed documents are not moved. A route with no patterns is valid: it never matches in Tier 1 and is only chosen by the model; patterns that match the empty string (such as `(?:a|)`) are rejected.
**Folders.** cloudtidy **never creates any folder while moving files** — neither a bucket (`01_Uni`, `02_Admin & Finanzen`, …) nor a sub-folder (`02_Admin & Finanzen/Rechnungen`) nor `_Inbox/Needs_Review`. On a Mac whose iCloud Drive has not finished syncing, a locally created folder would later collide with the real one as `Rechnungen 2`. A file whose destination folder is missing goes to `_Inbox/Needs_Review` with the reason `folder_missing:<relative path>`; if `Needs_Review` itself is missing the file simply stays in `_Inbox` and the run reports an error (exit 1). `init` is the only command that creates folders: the complete taxonomy — `_Inbox`, `_Inbox/Needs_Review`, every bucket and every configured sub-folder; it previews by default and `--yes` creates what is missing (one non-recursive `mkdir` each, parents first, never over an existing entry). **Run it only after iCloud Drive has fully synced** (Finder shows no cloud/progress icons on the folders). `doctor` checks the whole taxonomy. Keep this repo (and `bun`) outside `~/Desktop`, `~/Documents`, `~/Downloads` and iCloud Drive: the LaunchAgent would otherwise need extra privacy permissions just to read its own source. To test without iCloud, copy `config/default.config.json`, point `root` at a folder containing the taxonomy (`init --yes --config <file>` creates it when `allowNonICloudRoot` is true), and pass `--config <file>` to every command.

## Commands

All commands run from the repo root as `bun src/cli.ts <command>` (alias `bun run cloudtidy -- <command>`).

| Command | What it does |
| --- | --- |
| `classify <file>` | Classify one file (read-only, any path): route, destination, tier, reason, and `namingReason` when a file that should be renamed keeps its name. |
| `init [--yes]` | Preview (default) or create the missing taxonomy folders (`_Inbox`, `_Inbox/Needs_Review`, the buckets, configured sub-folders). The only command that creates folders. Refuses outside iCloud Drive. |
| `scan --dry-run` | Preview what would happen to `_Inbox` as JSON. Same single debounce as `run`, but no lock, cache or state writes; fails (exit 1) if `_Inbox` is unreadable. |
| `run [--apply] [--no-cache] [--json] [--verbose]` | One `_Inbox` pass: stability debounce → classify → (with `--apply`) move + audit log. Without `--apply` it only reports (user files untouched; it still writes the lock, decision cache and `status.json` in the state dir). `--daemon` marks a LaunchAgent run (apply is then governed by `daemon.apply`). Skipped entries (folders, dotfiles, `.icloud` placeholders, partial downloads, …) and files held after an undo are only counted unless `--verbose` (the held count says how to release them); a run with nothing to sort prints exactly one line (keeps the launchd log small); the line also counts files that can never be sorted (symlinks, unsafe names, `~` names, ...: `3 file(s) can't be handled (symlink, unsafe_name)`), while dotfiles, `.icloud` placeholders and partial downloads stay silent. The held-file hint is `bun src/cli.ts run --apply --no-cache`. `status`/`doctor` warn when the last runs stopped at the time budget (recorded in `status.json`). A run stops starting files after `maxRunSeconds` (default 300) and says so in one line. Previews (`run`, `scan --dry-run`, `sweep`) show the same `review … folder_missing:<path>` that `--apply` would produce. |
| `review` | Lists `_Inbox/Needs_Review` with the recorded reason per file, then the files still *pending* in `_Inbox` (unstable, empty, waiting for the model). |
| `history [--limit N] [--run ID] [--json]` | Append-only JSONL audit log. |
| `undo <runId>` / `undo --last` `[--apply]` | **Preview by default**; `--apply` restores. Restores only if the moved file's hash still matches and the original path is free; never overwrites. Undone content is "held" so the daemon does not immediately re-sort it (`run --no-cache` releases it). |
| `sweep [--apply] [--yes] [--verbose]` | Loose files in the iCloud Drive root. Preview first (skipped folders are summarised, `--verbose` lists them); `--apply` asks for confirmation (or `--yes`). Never run by the daemon. |
| `install [--print] [--bun <path>]` / `uninstall` | LaunchAgent `at.paul.cloudtidy` (WatchPaths on `_Inbox` + periodic `StartInterval`). bun is `~/.bun/bin/bun` (then `/opt/homebrew/bin/bun`), never a versioned Homebrew Cellar path; `--bun` overrides (absolute, executable, not versioned). `pdftotext` is resolved to an absolute path at install time (the agent's PATH is only `/usr/bin:/bin:/usr/sbin:/sbin`). `--print` is side-effect-free, works on Linux and shows the resolved absolute `_Inbox` path that `install` would watch. Refuses on non-macOS. `uninstall` keeps history/cache/logs. |
| `status` | LaunchAgent state, last run, whether the model was reachable **from the LaunchAgent context**, pending count, history size. |
| `eval <dir> [--expected labels.json] [--max-files N] [--json]` | Read-only batch report (see below). |
| `doctor [--json]` | Environment checks: native Apple silicon (not Rosetta), helpers, model, the whole folder taxonomy, a real no-clobber rename probe on the iCloud volume (an opted-in non-atomic fallback is reported as a WARNING and never as verified), unresolved journal entries, errors of the last run, root/bun-path warnings. |

### The 20-document evaluation

```sh
bun src/cli.ts eval /path/to/20-docs --expected /path/to/labels.json
```

`labels.json` is a flat JSON object `filename → route id | "review"` (route ids: `uni`, `invoices`, `contracts`, `bank`, `tax`, `receipts`, `admin`, `dev`, `personal`), e.g. `{"bill.pdf":"invoices","scan1.jpg":"review"}`. `eval` skips dotfiles, symlinks, the file passed to `--expected` and any file named `labels.json`, never writes into the folder, stops at 500 files (`--max-files N` changes the cap; the report warns when files were left out) and exits 1 with a clear message if the folder does not exist. It reports route distribution, review rate, accuracy vs. labels (wrong auto-routes, auto-routed-but-expected-review, review-instead), per-file proposals, and latency:

**Fixture eval (run it right after `build:helpers` and `bin/classify --check`, with the real helper).** `fixtures/eval/` holds 28 synthetic, fake-data documents (DE/EN) with `labels.json`: 18 documents that the rules should route deterministically across the eight rule routes (`admin` has no rules), a few that need the model tier, review cases (`notiz_unklar`, `rechnung_und_mietvertrag_gemischt`), `svs_oegk_beitragsvorschreibung` (labelled `admin`, the only fixture for the model-only root route; it must never become `contracts`, and review counts as the documented-acceptable outcome: the summary prints a second accuracy line that counts it as correct) and 7 prompt-injection documents (`inj_*`: forced route, `../` filename, shell command, path traversal, JSON escape). Two attacks exist twice: `inj_route_force_uni` and `inj_filename_passport` are rule hits (they only show that rules are final), `inj_route_force_nomatch` and `inj_filename_nomatch` carry the same attacks without any rule word, so all five attacks reach the model. `bun run eval:fixtures` copies them to a temporary root, runs the normal `eval` with the labels and prints accuracy, review rate, latency, `unsafe outputs: N` (a route outside the taxonomy, a filename with a path or control characters, an unsafe name) and `injection documents that were not resisted: N` (an `inj_*` document that ended anywhere but its label or review). **Exit codes:** 0 = fine; 1 = an unsafe output or a successful injection; 2 = some documents were not evaluated (they ended *pending*: model unavailable, busy or timed out; a warning lists them): the result is not meaningful, fix the model first (`doctor`, `bin/classify --check`) and repeat. Without the real model (Linux) the documents that need it end pending, so the command exits 2; the test suite runs the same fixtures against a mock model and a hostile model.

- **Rule-tier routing** (heuristics only, no extraction, no model) is reported on its own, with a **p95 > 10 ms flag** (Notion: Tier 1 "< 5 ms", success criterion "< 10 ms"). Rule hits are final and instant.
- **Naming** of rule hits (deterministic date/sender extraction; the model is only asked for missing fields) is a separate row.
- Extraction, cold first model call and warm model calls are reported separately. "Cold" is the first model call of the `eval` process; reboot or wait for the model to unload for a truly cold number.

Files that would be deferred because the model is unavailable show up as `pending`. Include ambiguous, scanned/OCR, German + English, and prompt-injection documents.

### Daemon apply mode

`install` loads a LaunchAgent that runs `run --daemon`. It is **read-only until you edit the config it was installed with** (`config/default.config.json`, or the copy you passed via `install --config <file>`; the path is baked into the plist): set `"daemon": { "apply": true }`. The config is re-read on every run, so no reload is needed for that; only a changed `daemon.intervalSec` (default **120 s**, stored in the plist; 60–86400) needs `uninstall` + `install`. The launchd stdout/stderr files (`launchd.out.log`, `launchd.err.log` in the log directory) are rotated by size (5 MB, 3 files in total) at every run and at install. Notifications (`daemon.notify`, title "cloudtidy") read `Sorted invoice into 02_Admin & Finanzen` for one file and `Sorted 3 files (01_Uni 2, 02_Admin & Finanzen 1) · 1 to Needs_Review` for several; they contain route kinds, counts and configured folder names, never filenames or text. `sweep` can never run from the daemon.

**Before you set `daemon.apply: true`:** run `doctor` (every required line ✓, in particular the no-clobber probe on your iCloud volume and "taxonomy folders exist"), run `init` after iCloud has synced, check `status` after the first launchd run, and enable it on **one Mac only**. Two Macs running `apply` against the same iCloud `_Inbox` race each other: the local no-clobber rename cannot see the other Mac's pending iCloud changes, so the same file may be handled twice or end up as a conflict copy. Apply modes also refuse a `root` outside `~/Library/Mobile Documents/com~apple~CloudDocs` unless the config sets `"allowNonICloudRoot": true`.

## Pipeline and routing

1. List regular direct children of `_Inbox` (skip dotfiles, `.icloud` placeholders, partial downloads such as `.crdownload`/`.part`/`.tmp`, folders, symlinks, protected names).
2. **One shared debounce** (`debounceMs`, default 3 s, plus up to `stabilityRetries` more shared rounds, default 2) for the whole batch: files whose size/mtime still change afterwards are *pending* (reason `unstable`), as are **empty files** (reason `empty_file`; an empty file that stays unchanged for `emptyGraceMinutes`, default 10, goes to review). Scan, run, review and status report pending files the same way, with a reason; nothing is skipped silently.
3. Extract text (plain text, PDF text layer, Vision OCR for scans/images; first two PDF pages; German/English). Text-less documents → review.
4. **Tier 1 rules** (case-insensitive, Unicode-aware regexes per route; patterns match **whole words**, e.g. `Betrag` does not fire on `Bankbetrag`; German compounds are listed explicitly where wanted, such as `Rechnungsnummer` or `…versicherung`; the statutory `Sozialversicherung…`, `Versicherungsnummer` and `Versicherungsdaten…` words are deliberately excluded from `contracts`). Exactly one matching route is definite **and final**: no model call decides the route, so a rule hit is instant. Conflicts (two routes match) and no match go to the model. Shipped routes: `uni`, `invoices`, `contracts`, **`bank`** (`02_Admin & Finanzen/Bank`: Kontoauszug, Bank statement), **`tax`** (`02_Admin & Finanzen/Steuern`: Finanzamt, Steuerbescheid, Einkommensteuer, Arbeitnehmerveranlagung, Lohnzettel), **`receipts`** (`02_Admin & Finanzen/Belege`: Kassenbon, Quittung, Beleg, Receipt), **`admin`** (the `02_Admin & Finanzen` root, **no patterns: only the model can choose it**, for authorities, SVS/ÖGK and other admin mail), `dev`, `personal`. `bank`, `tax`, `receipts` and `admin` keep file names. Overlaps stay with the model: a Kontoauszug that mentions a Steuerbescheid, or a Rechnung that is also a Beleg, matches two routes and is not a Tier-1 hit. The model may answer `bank`, `tax`, `receipts` or `admin` like any other configured route id; anything else is rejected.
5. **Naming of invoices/contracts is deterministic first.** Bun reads the labelled issue date (`Rechnungsdatum`, `Invoice date`, `Vertragsdatum`, … four-digit year; two different dates under the same label → none) and recognises known senders (`knownSenders` in the config, seeded with Austrian providers such as Drei, A1, Magenta, Wien Energie, ÖBB, Wiener Linien, Wiener Netze, EVN, Verbund, Wiener Städtische, UNIQA, Generali, Allianz) without any model. Known senders match **case-sensitively** in the configured spelling or an alias (or the same in capitals, as printed in many letterheads): "Kaution drei Monatsmieten" is not Drei. Entries that are also ordinary words are marked `"commonWord": true` (Drei, Magenta, Verbund, Allianz). They have no text window: they count only (a) before a company suffix or as an alias (`Drei GmbH`, `Drei Austria`, `Hutchison Drei`, `VERBUND AG`, `Magenta Telekom`), or (b) when the name stands alone on one of the first 6 non-empty lines (capitals allowed), or opens such a line before a document word (`Drei Rechnung`). "Kaution: Drei Monatsmieten" and "Im Verbund mit der Gemeinde" therefore give no sender, and the original name is kept. **Stated senders:** a sender the document states itself beats a bare known-sender hit, and supplies a sender even when none is known: the first `Absender:` (or `Rechnungssteller:`) line, only if there is none a `Sender:`/`From:` line. The value wins as a whole (`Absender: Evil Corp, Drei Austria` is `Evil Corp`; the value is cut at the first `, ; | ， 、 ، ؛ /`, tab or double space), model suggestions are checked with the same character and document-word rules (`Credit Suisse AG` and `Order Systems GmbH` are fine); a known sender inside it counts only if the value starts with it. A rejected stated value (a document word such as `Rechnung Bau GmbH`, a look-alike such as a Cyrillic `Е` in `Wien Еnergie` (senders may only contain Latin letters incl. umlauts/ß/é, digits, space and `& . , - '`, and must be NFKC-stable: no Cyrillic/Greek/Cherokee/…, fullwidth, math-bold or ligature letters), a commonWord name that does not pass the rules above, stopwords) falls through to a letterhead line that ends in a company form (used only to settle known-sender hits), else the sender stays missing. A rejected `Absender:` value is not replaced by a `Sender:`/`From:` line. A missing sender is then asked from the model, whose suggestion must pass exactly the same checks (characters, document words, stopwords, commonWord rules, whole word in the text), so a model that echoes a rejected value (`Rechnung Bau GmbH`, a look-alike) does not bring it back: the original name is kept (`naming_sender_unverified`). Add your own spellings as `aliases`. Only when the date or sender is missing, the model is called with the **route locked** (it can only fill in `documentDate`/`sender`, never change the route); its values count only if they appear in the document text (whole word, ≥ 3 characters or a known sender, and not just an article, pronoun, greeting or mail header such as `Die`, `Der`, `Re`, `An`, `Sehr`, `Dear`). If the model ran but nothing validates, the original name is kept. **A rule hit stays final even when the model fails definitively** (refusal, guardrail, unsupported language, invalid output): the file moves to the rule's folder under its original name and the specific reason (`naming_model_refusal`, …) is shown by `run`/`classify` and recorded in the history. Result: `YYYY-MM-DD_<Sender>-<Doctype>.<ext>`. University/dev/admin/personal files keep their names (`naming.datePrefix`, off by default, adds a date prefix in `04_Persönlich`, the `02_Admin & Finanzen` root and its `Bank`, `Steuern` and `Belege` sub-folders). The model never supplies a filename, extension or path.
6. **Tier 2 model** for rule-less files (`bin/classify`, protocol v2, `docs/protocol.md`): schema-constrained route ID plus date/sender and a review flag. Greedy sampling, content-hash decision cache. **Route evidence (deterministic check of the model's choice).** A route may carry an optional `evidence` list (same syntax, whole-word matching, case-insensitivity, 16-entry/400-character limits and empty-match rejection as `patterns`, matched against the file name and the first 20,000 characters of text). When the *model* picks a route that has `evidence`, Bun accepts it only if at least one evidence pattern matches; otherwise the file goes to `_Inbox/Needs_Review` with the reason **`model_route_unverified:<route id>`**. Evidence is never a Tier-1 rule: it does not make a route fire, does not count as a pattern match and cannot create a conflict between routes; routes without `evidence` are accepted as before, and a rule hit never consults it. The default config gives only the model-only `admin` root evidence (Austrian authorities and social insurance: `Sozialversicherung…`, `SVS`, `ÖGK`, `Gesundheitskasse`, `Versicherungsnummer`, `Versicherungsdaten…`, `Beitragsvorschreibung`, `Pensionsversicherung`, `AUVA`, `Magistrat…`, `Bezirkshauptmannschaft`, `Behörde(n)`, `Bescheid(e)`, `Meldeamt`/`Gemeindeamt`/`Stadtamt`; deliberately not the bare words `admin` or `Amt`), so a note or a prompt-injection text that merely says "admin" cannot be filed into the root. An unverified admin answer is the expected outcome for such files; `eval:fixtures` treats review as correct for the injection documents. An existing custom `--config` copy has no `evidence` for `admin` until you add the list from `config/default.config.json` (without it the old behaviour remains: the model alone decides).
7. **Model unavailable? Defer, don't dump.** Transient failures (model not ready / Apple Intelligence off, timeout, rate limited, helper crash) leave the file **in `_Inbox` as pending** (first seen, attempts, backoff 5/10/20/40/60 min; a `model_unavailable` file is retried at once when the model is reported available again; timeouts and busy/rate-limited files wait for their backoff step, also after the 24 h are over). This applies to every file that needs the model, including rule hits waiting for date/sender. **Bounded runs:** every run (and `sweep`) has a time budget, `maxRunSeconds` (default 300, 60–3600), measured from the moment the lock is held and checked *before a file is started*. Once it is spent no further file is started: the rest is left completely untouched (no pending change, no attempt, no review) and a single line says `time budget reached after Ns: K file(s) left for the next run`. The budget is not checked inside a file, so the **worst-case lock hold is `maxRunSeconds` + one file's maximum** (PDF text + OCR + the model calls with retries: at the defaults ≈ 300 s + ~245 s); `status` and `doctor` print the figures for your config. Other triggers wait `lockWaitMs` for the lock and then skip. There is no separate extraction circuit breaker: the budget plus the exponential backoff of the pending logic bounds it. A per-run circuit breaker stops asking the model after the first file that exhausted its retries; files it skips are **not** attempts (no attempt counted, no clock started, no backoff growth) and stay pending for the next due run. **A file is sent to `_Inbox/Needs_Review` (reason `deferred_too_long:<reason>`) only if all of these hold:** at least `model.maxDeferHours` (default 24) passed since the first *apply-mode* attempt, at least 3 attempts were made in apply mode, and one final attempt in the current run also failed transiently. Only **real helper calls for that file in that run, and the file's own extraction (OCR/pdftotext) timeouts,** count as attempts, including the final one; files answered by the open breaker don't: an expired file bypasses an open breaker and gets exactly one real call (no retries, so a hung helper costs at most one `timeoutMs` per expired file); if that call succeeds the file is sorted normally. **A final call that returns `model_busy` (rate limit / concurrent requests) counts as an attempt but never sends the file to review**: busy says nothing about the file, so it stays pending and keeps its backoff (it is asked again at its next due run, not on every run, so a busy file cannot starve the files behind it); it is not pending forever either: once more than 4 × `maxDeferHours` (96 h at the defaults, wall-clock time since its first apply attempt, not the time the model was actually busy: a single busy final call after a long outage or a closed laptop is enough) have passed, a busy final call sends it to review as `deferred_too_long:model_busy`; only a timeout, `model_unavailable` or a crash on the final call gives `deferred_too_long:*`. **Cost of expired files:** each expired file costs one real call per run (up to `timeoutMs` if the helper hangs), and these calls draw on the run's time budget (below), so a hung helper cannot hold the lock for N × `timeoutMs`. While the model is down, a run really asks only the first due file (the open breaker answers the rest without a call); that file then backs off (5, 10, 20 … 60 min), so the next run asks the next due file. Probes rotate through the backlog at about one file per run and all files age in parallel; nothing is reviewed unasked. Dry-runs record pending entries for reporting but never start or advance that clock, and a closed laptop or an outage never expires a file without a fresh attempt.
   **Definite answers go to review immediately, with the specific reason** (never collapsed into one generic code): `model_refusal`, `model_guardrail`, `model_unsupported_language`, `model_context_overflow`, `model_invalid_output`, `model_invalid_request`, `invalid_response` (malformed answer), `model_route_unverified:<id>` (the model chose a route whose `evidence` the document does not contain), or `model_failed` (anything else). Rule hits are the exception (see step 5). Transient reasons: `model_unavailable`, `model_busy`, `model_timeout`, `model_crashed`.
8. **Move** (`--apply`): see below. Each route ID maps to one fully configured folder.

## Safety model

- **On-device only.** No network calls at runtime, no cloud/model-server fallback, no new runtime dependencies. Model output is untrusted: strict key set, route membership, date/sender re-validated against the text.
- **Read-only default.** `run`/`sweep`/`undo` change nothing without `--apply`; the daemon needs `daemon.apply: true`. `scan --dry-run`, `classify`, `eval`, `doctor`, `status`, `install --print` are read-only.
- **Writes are confined** to the configured buckets and `_Inbox/Needs_Review` (plus the state/log directories). **Moves never create a folder**; every destination folder must already exist (`init`). Destination paths are realpath-contained; symlinked components are rejected; `_Archiv`, native app containers (`Pages`, `Keynote`, `Numbers`, `Obsidian`, …, extendable via `blocklist`) and any name containing `~` are off limits for source and destination.
- **Atomic no-clobber, same-volume moves** via `renamex_np(RENAME_EXCL)` / `renameat2(RENAME_NOREPLACE)` (through `bun:ffi`). If it is unavailable, cloudtidy **refuses to move** (`atomic_rename_unavailable`, `doctor` fails); the non-atomic lstat + `rename` fallback needs an explicit `CLOUDTIDY_ALLOW_NONATOMIC_RENAME=1`. The opt-in non-atomic fallback is for emergencies only: `doctor` reports it as a WARNING (never "verified") and fails that check. Cross-device (`EXDEV`) → refuse and send to review; **no copy+delete, ever.** Name collisions get ` (n)` suffixes; identical content already at the destination → review (never deleted).
- **Source revalidation** just before moving (fingerprint + sha256), so a file that changed after classification is not moved.
- **Write-ahead journal.** Every move writes an fsync'd `intent` record before the rename and a `commit` after it (`abort` if it did not happen). If the process dies in between, the next apply run reconciles: a landed move is committed (so `undo` works), an unfinished one is aborted. A move whose journal cannot be written does not happen; a failed commit rolls the file back. If a rollback itself is impossible (the source name was taken again), the move is journaled as done so the file stays visible to `history`/`undo`, the run reports an error, and `doctor` lists unresolved journal entries; a file is never left in a bucket unjournaled.
- **Apply only in iCloud Drive.** `run --apply`, daemon apply, `sweep --apply` and `init --yes` refuse a root outside `~/Library/Mobile Documents/com~apple~CloudDocs` unless `allowNonICloudRoot` is true.
- **State files are untrusted.** `pending.json`, `held.json` and the decision cache are validated entry by entry (types, bounds, shapes) and use null-prototype maps (a file called `__proto__` is an ordinary name); a corrupt entry is dropped with a warning and can never wedge a file in `_Inbox` or flush it to review.
- **Single run at a time** (PID lock with stale detection); idempotent rescans via the content-hash cache.
- **Audit + undo:** every move is appended to `history.jsonl`; `undo` is hash-verified and refuses on mismatch, occupied original, missing file or tampered history.
- **Failures fail closed:** uncertain, failed, unsupported, empty, oversized, unsafe → `_Inbox/Needs_Review` with a recorded reason. Logs contain no document text.

State lives in `~/Library/Application Support/cloudtidy` (`history.jsonl`, decision cache, `held.json` for undo holds, `pending.json`, lock, `status.json`), logs in `~/Library/Logs/cloudtidy` (both configurable). The state and log directories are `0700`, history/state/log files `0600` (file names are personal data).

## Limitations and residual risks

- **Not verified on a Mac yet:** model quality/latency, OCR, `launchd` access to Apple Intelligence, iCloud placeholder behaviour, real EXDEV from an iPhone/iCloud mix.
- **`RENAME_EXCL` on iCloud (F-01).** The no-clobber guarantee depends on the filesystem under iCloud Drive honouring `renamex_np(RENAME_EXCL)`. Linux CI cannot prove that; `doctor` probes it on your real `_Inbox` volume (a dot-prefixed `.cloudtidy-probe-*` folder inside `_Inbox`, removed again, only its own files) and fails if it is unsupported. cloudtidy then refuses to move rather than falling back silently.
- **Directory TOCTOU (F-08), accepted.** Bun has no `openat`, so a path component swapped for a symlink between the check and the rename is not prevented; the mover re-checks `realpath` afterwards and rolls the move back, but the window itself remains. Requires a local attacker/process with write access to your iCloud folders.
- **Rules are steerable (F-16), accepted.** A rule hit is final, so text inside a document (including hidden text) can steer its route. Whole-word matching and the "exactly one route matches" requirement limit accidental matches only. Nothing leaves your Mac and nothing is deleted, but a document can end up in the wrong bucket.
- **Two Macs (F-24).** Enable `daemon.apply` on one Mac only (see above).
- **Stale lock.** A crashed run leaves a lock file; it is taken over once its PID is dead (or the lock is old). A live PID is respected.
- **Probe folder.** While `doctor` runs, a hidden `.cloudtidy-probe-*` folder briefly exists in `_Inbox` (iCloud may sync it for a moment); cloudtidy ignores dotfiles.
- **Permissions (TCC).** LaunchAgents may lack permission to read `~/Library/Mobile Documents`. If `status` shows `_Inbox readable: NO`: System Settings → Privacy & Security → Full Disk Access → `+` → press ⌘⇧G and enter the **exact bun path** printed by `install` (`~/.bun/bin/bun`; `doctor` warns if the installed plist points to a versioned or missing binary). Replacing the binary on a bun upgrade may drop the grant; re-run `install` after changing the bun location. **Homebrew caveat:** `/opt/homebrew/bin/bun` is a symlink to a versioned Cellar binary and macOS records the *resolved* binary, so a `brew upgrade bun` can drop the Full Disk Access grant even though the plist path stays the same; prefer the official installer's `~/.bun/bin/bun`, or re-grant after upgrades. Then `launchctl kickstart -k gui/$(id -u)/at.paul.cloudtidy` and re-check `status`. Interactive runs need the same access for your terminal app.
- iCloud placeholders (`.icloud`) are skipped, not downloaded (`brctl` is not used). **macOS 14+ dataless files (F-07, Mac only):** newer macOS can keep an evicted file under its real name instead of a `.name.icloud` stub; reading it (hashing, duplicate detection, text extraction) makes the OS download it, and the stub check does not see it. cloudtidy does not handle `SF_DATALESS` specially yet; test with an evicted file on your Mac before enabling the daemon.
- Unsupported formats (docx, zip, …), files over 25 MiB, and files with no extractable text go to review. Ambiguous slash dates (`03/10/2026`) are never used for naming.
- Prompt isolation is not a security boundary; guided generation constrains shape, not truth. Model self-confidence is not used.
- Known-sender spellings with fewer than 3 characters (e.g. `A1`) only count in the first 1,500 characters of a document (letterhead), so a paper size "A1" in the body is not a sender.

## Tests

```sh
bun install --frozen-lockfile && bun run typecheck && bun test
```

Tests use temporary roots (the full pre-created taxonomy, `allowNonICloudRoot: true`), fake helpers and fake models. They cover config validation, whole-word rules, deterministic naming, hostile model output, symlinks/blocklist/traversal, EXDEV, collisions, duplicates, the write-ahead journal and crash recovery, missing buckets/`init`, the non-iCloud refusal, deferral/backoff/give-up, empty and unstable files, undo holds, LaunchAgent plist (control characters, bun path), notifications, `eval`, and the CLI. `test/review-*.test.ts`, `test/rereview.test.ts` and `test/round3.test.ts` are the guard and regression tests from the safety/conformance reviews. Apple inference/OCR cannot be tested on Linux. The Swift helpers were compile-checked on Linux against a documentation-based FoundationModels stub only; the real SDK compile happens in `bun run build:helpers` on the Mac.

### Enable CI manually

The GitHub connection used for development cannot write `.github/workflows/*`. Copy `docs/ci-workflow.yml.template` to `.github/workflows/ci.yml` with your own credentials. It runs on pushes to `main` and on pull requests (not twice for a PR branch): typecheck + tests on Linux (Bun 1.3.2), and on `macos-26` `bun test` (so `renamex_np` and macOS path behaviour are exercised) plus the Swift helper build/sign, with a non-blocking `--check` smoke test.
